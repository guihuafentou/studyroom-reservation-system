## 二、分级问题清单

- **致命：无**
- **重要：无**
- **建议（低优先，不影响交付）：**
  1. `coveredSeatIds`/`visionAvailable` 发布非原子。`syncSeatStatus` 先置 `visionAvailable=true`、再 `clear()+addAll()`，与 `scan()` 是两个独立 `@Scheduled` 线程。理论上并发时存在微秒级窗口误判"未覆盖→直接违约"。建议把两者合并为单个 `volatile` 快照字段原子发布（如 `volatile VisionSnapshot`，用 `Map.copyOf`/`Set.copyOf` 一次性赋值）。
  2. `handleTimeoutViolations` 中空 `if` 分支仅靠注释承载语义（`vision-service` 空 if + else），可读性差。建议改写为正向条件：`if (visionService.isSeatCovered(seatId) && visionService.emptyMinutes(seatId, now) == 0) continue;`，去掉空分支。
  3. 视觉服务重启后首轮 `/detect` 因 `background_ready=false` 返回 `results:[]`（约 5 秒窗口），此窗口内 room-1 会被短暂当作"未覆盖"。概率极低、影响可忽略，但与建议 1 同源（快照为空），可一并由快照方案缓解。
  4. README §三 "21 个类" 与实际约 46 个 Java 类不符，属文档口径小瑕疵。
